(Dated: October 14, 2026) We construct Clifford+ T circuits implementing arbitrary n-qubit unitaries with worst-case T -count eO(N 8/7) at constant operator-norm error, where N = 2 n, improving the previous exponent 5/4. The construction uses eO(N 6/7) clean ancillas. The main idea is to reduce the data addressed by each query to the block-encoding circuit for a sparse piece while controlling the additional simulation work needed to combine the pieces. We simulate a Hermitian logarithm of the target by flattening its traceless part with a two-layer random similarity transformation, randomly partitioning the transformed generator into block-sparse Hermitian pieces, and combining their evolutions using qDRIFT. For a target operator-norm error ϵ ∈ (0 , 1/2), let L = log 2(N/ϵ ), the qubit count plus the requested bits of accuracy. By successively correcting the approximation error, we obtain a circuit using eO(N 8/7L3/7 + N L ) T gates and eO(N ) clean ancillas whenever L ≤ N . We also prove that, at constant precision, the exponent 8 /7 is optimal within a sequential block-SELECT model. 

I. INTRODUCTION 

In fault tolerant quantum computing, non-Clifford gates are often substantially more expensive than Clif-ford gates. For example, implementations using surface codes [1] can supply the gate T = diag(1 , e iπ/ 4) through magic state distillation [2]. This motivates using the number of T gates as a resource measure, distinct from the total gate count, and has led to extensive optimiza-tion of small circuits [3–5]. Here we ask: how many T

gates are needed to implement an arbitrary unitary on n

qubits to accuracy ϵ?

For N = 2 n, a generic unitary has N 2 real parame-ters. The challenge is to incorporate these parameters into a Clifford+ T circuit using few T gates. At con-stant precision, a polynomial gap remains between the known bounds on the number of T gates required in the worst case. Counting gives a lower bound of Ω( N ) [6, 7]. Low et al. [8] give an upper bound eO(N 3/2). Tan [7] re-duces the exponent to 4 /3 by combining recursive cosine– sine decomposition with the synthesis of multiplexed di-agonal unitaries. Yuan et al. [9] obtain exponent 5 /4through random block flattening, dilation, and singular value transformation. Fang et al. [10] use a different ap-proach based on a logarithm to obtain bounds that de-pend on the target unitary, with eO(N 3/2) T gates in the worst case. Related work studies depth and ancilla tradeoffs us-ing continuously parameterized gates [11–17]. Oracle formulations count Boolean queries as primitive opera-tions [12, 18–23]. A recent construction gives synthesis in polynomial time at constant error in the diamond norm, using a suitably chosen oracle that depends on the tar-get [24]. Here we count the T gates needed to implement the complete circuit, including the synthesis of elemen-tary gates and the implementation of data access. We obtain the following bound by combining encod-ings of block-sparse matrices with Hamiltonian simula-tion and residual refinement.

III. OVERVIEW OF THE CONSTRUCTION 

Our construction reduces the data addressed by each query to a piece’s block encoding. We use Tan’s select 

oracle synthesis bound [7] (Lemma 2) for data access. Yuan et al. [9] encode the full unitary and repeatedly use that encoding for singular-value amplification. We sim-ulate a Hermitian logarithm using s separately encoded block-sparse pieces, with few nonzero blocks per block row and column. Each piece has a smaller lookup table. qDRIFT [25, 26] combines their evolutions. Balancing the cost per query against the number of queries yields the eO(N 8/7) T -count at constant precision. > VIII. DISCUSSION

We have constructed Clifford+ T circuits for arbitrary 

n-qubit unitaries using eO(N 8/7) T gates and eO(N 6/7)clean ancillas at constant operator-norm error, where 

N = 2 n. The construction combines random similarity flattening, a Hermitian block-sparse split, qDRIFT, and QSVT to reduce the lookup cost per query while con-trolling the total simulation work. Residual refinement gives eO(N 8/7L3/7 +N L ) T gates and eO(N ) clean ancillas for target error ϵ ∈ (0 , 1/2) with L = n + log 2(1 /ϵ ) ≤ N .Within the sequential block-SELECT cost model, the ex-ponent 8 /7 is optimal at constant precision under its in-terleaver information restriction. For synthesis using qDRIFT and QSVT at constant precision, the T -gate and ancilla bounds have prod-uct eO(N 2), matching Tan’s space– T -count tradeoff ( n +

manc )T = Ω( N 2) [7] up to factors polynomial in n. Com-pared with Tan’s construction, we use fewer T gates but more ancillas. This moves the costs closer to the bal-anced scale T ≈ manc ≈ N , though our upper bound remains above the general counting lower bound. Oracle-based synthesis uses a different cost accounting. OpenAI’s recent draft [24] establishes unitary synthe-sis at constant diamond-norm error using polynomially many elementary gates, qubits, and queries to a suitably chosen Boolean oracle. The target-dependent Boolean function has unrestricted truth-table size and circuit complexity, and the polynomial resource bound excludes the cost of implementing its oracle calls. This distinction matters when comparing with the Clifford+ T construc-tions of Tan [7], Yuan et al. [9], and this work. These constructions include the cost of quantum data access and achieve T -counts eO(N 4/3), eO(N 5/4), and eO(N 8/7), respectively. In the OpenAI theorem, p(n) bounds all resources, whereas m(n) ≤ p(n) denotes the oracle in-put length. A generic implementation uses O(2 m(n)/2)

T gates and ancillas per query, yielding a total T -count bounded by 2 m(n)/2 poly( n). A polynomial bound on 

m(n) alone therefore does not determine an exponen-tial scaling comparable with these synthesis bounds. For example, m(n) ≤ 2n + O(log n) would suffice to reach 

N poly( n) through generic oracle compilation, but the draft does not establish this bound or a comparably effi-cient implementation of its particular oracle. A quantita-tive comparison consequently requires accounting for the oracle’s implementation cost and ancillary workspace. Comparisons at finite size likewise require compiled resource estimates, because our bounds are asymptotic. Liu et al. [34] provide such estimates for state prepara-tion, comparing rotation- and sampling-based methods after compilation in both T -count and total gate count. For our construction, compiled estimates must account for its large lookup tables and substantial workspace. When the data have structure, compressed tables can reduce data-loading costs, as compact alias tables do for real-amplitude state preparation with polynomial ampli-tudes [35]. At constant target error, a polynomial gap remains between our eO(N 8/7) upper bound on T -count and the general counting lower bound eΩ( N ). It remains open 13 whether general Clifford+ T circuits can achieve a smaller exponent and ultimately reach the counting scale. Our matching N 8/7 lower bound relies on a counting argu-ment within the sequential block-SELECT cost model under its interleaver information restriction. A comple-mentary question is whether a worst-case lower bound of Ω( N 1+ c) T gates, for some fixed c > 0, can be proved for general circuits with an unrestricted number of clean ancillas. Workspace raises a further question at higher precision, where residual refinement uses O(nN ) clean ancillas throughout L ≤ N , independently of ϵ. How much of its T -count improvement can be retained with fewer ancillas? Similar questions arise beyond qubits. Approximate single-qutrit Clifford+ R synthesis has been studied [36]. For arbitrary unitaries on many qudits, the optimal non-Clifford gate count at constant error remains open.

> 4. Effective classical compilation

The constructions underlying Theorems 3 and 4 treat matrix logarithms, exponentials, norms, comparisons, rounding, and sampling from exact finite distributions as oracle operations. Their probability estimates bound the expected number of resampling trials by a constant for the constant-precision construction and by O(n + L/n )in total for the refined construction. These trial counts do not bound classical running time: the oracles need not have unit cost on a rational-arithmetic RAM, and certified entry approximations alone may not decide zero tests or rounding ties. Finite circuit search avoids these decisions by using the strict error margins in the existence proofs. It yields the following computability guarantee, with no polynomial bound on classical compilation time.
